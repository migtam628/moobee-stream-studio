## Revision-bound destination editing
Saved destination edits replace the complete OS-vault record under the process-local store lock and keep the existing UUID index marker. Each successful edit generates a new non-secret revision, including key-only changes. Native single and multistream credential leases compare destination name, URL and revision to the reviewed selection; stale reviews fail closed. Existing records lacking a revision remain readable and receive a revision on first edit. A different server URL requires a newly entered key; changing only the label can retain the existing key. Active leases block editing and deletion. No current key is returned to the renderer or saved outside the vault. The OS vault's write guarantees and external modifications across processes are not independently verified; revision checks do not establish an independent native consent boundary against a compromised renderer. Physical credential store and streaming acceptance remain pending.
