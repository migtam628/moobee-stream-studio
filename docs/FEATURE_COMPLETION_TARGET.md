The previous 75% milestone is not a stopping point. This is a development coverage metric, not a time estimate, feature-parity percentage, or production readiness score. A primitive, mock, prototype, open PR or isolated codec does not satisfy an integration gate by itself. A workstream may be implemented for a bounded diagnostic while hardware acceptance remains pending; the documented scope must be visible in the UI.

## Worker/producer increment
The dedicated publishing worker takes ownership of an already authorized Session with a finite-deadline transport. It uses a 128-packet/8 MiB bounded mailbox, atomic producer batch admission, independent pacing ticks, explicit stop/failure, 5-second producer inactivity failure, nonblocking status/reaping, and fail-closed queue overflow. The macOS producer combines VideoToolbox AVC and native AAC on a nominal frame/sample timeline, supplies codec configurations before media and forces an IDR at startup and nominal two-second intervals. Capture and device ownership remain with the future orchestrator. Tests use a simulated server; the combined native synthetic encoder test is opt-in, not a physical test. The worker does not autonomously connect to any destination. Inbound signaling requires an owner that can ensure a complete chunk can be read; socket/TLS readiness, connection startup/cancellation, live capture integration, actual streaming, Windows live packets and receiving-side verification remain outstanding. Stop is cooperative and may wait for an existing bounded I/O call. No installer or release is authorized.

## Native Program live-packet diagnostic
The Mac-only offline FLV test now routes the existing native Program capture worker's composed RGBA and aligned optional PCM into the actual VideoToolbox AVC / AAC packet producer. The diagnostic uses the same packet validation rules as the live publishing queue. It writes validated FLV tags incrementally to a private UUID temporary file and publishes only after successful finalization with at least two video packets, required AAC media when selected, file sync and no-replace publication. Limit: 2–8 seconds, 64 MiB, one named video device or up to four displays; separate webcam inset off. Existing source layout/transforms/filters, static overlay, and named audio mixing are reused. No network connections, stream keys, remote destinations, live worker invocation, pause/take controls, or live UI activation. Reported duration is nominal submitted-frame duration, not independently measured file playback; AAC startup/tail delay is not flushed or corrected. Independent full decode (e.g. ffprobe/FFmpeg) and physical capture QA remain necessary. Use Studio > Capture diagnostics > Offline streaming packet FLV test; reveal the private clip and test it externally. Failed diagnostics never publish incomplete media. This advances workstream 9 but does not complete it or increase the 8/20 core coverage count. 

## Priority 7J — RTMPS transport control integration
The new branch adds a non-mutating RTMP chunk length check, bounded decrypted input buffering (two maximum chunks plus header overhead), incremental inbound chunk processing, native TLS nonblocking read polling, periodic inbound polling by the publishing worker and bounded end-of-input drain. A fragmented header or body remains buffered until a complete chunk arrives. The explicit worker connection constructor uses existing certificate/hostname validation and publish authorization; there is no automatic connection at app launch or from a UI command. Server stop and control failures terminate the worker, and a successful drain closes only after the admitted media queue is empty. This is transport-level completion, not real broadcasting or graceful RTMP unpublish: OS DNS may block the connection caller, socket writes remain synchronous, and platform-specific nonblocking TLS behavior requires real receiving-side testing. Tests cover fragmented chunks, ping response, automatic polling, drain and failure with simulated transports. Native capture-to-network wiring, start/stop authorization UI, credential storage, reconnect, long-running soak, actual stream reception and hardware playback remain incomplete. All 20 workstreams plus formal production acceptance remain the final target.

## Priority 7K — Native Program to authorized publisher
Adds an internal macOS capture entry point (not a registered Tauri command). Explicit destination authorization and a validated secure URL/key are required before opening sources; cancellation is checked before capture, before connection and after negotiation. The existing composed Program loop feeds RGBA and matching stereo PCM to a same-thread AVC/AAC encoder and bounded publisher mailbox, without creating a clip file. The 2–60 second diagnostic uses one selected video device or up to four displays, the existing transforms/static overlay and optional named audio; no separate webcam inset, pause or scene take. It holds the existing capture lock, stops on cancellation/source/encoder/queue failures and drains admitted packets at successful end. The report identifies RTMPS and counts sent payload bytes rather than recording file bytes, with no file path; it is not receiving-side proof. A pre-media cancel or fewer than two complete ticks returns an error rather than reporting successful output. No UI invocation or automatic connection exists. TLS setup remains blocking on the capture worker, DNS has no cancellation deadline, source startup and backlog behavior need physical QA, and AAC tail delay remains uncorrected. A failed drain requests worker termination but cannot forcibly interrupt an outstanding socket write. Secure credential storage and explicit UI lifecycle, Windows live encoder, reconnect and receiving-side testing remain outstanding. Added rejected/cancelled request tests and opt-in native encoding-to-simulated-server regression. No real streaming, installer or release has been performed. Core workstream coverage remains 8/20.

## Priorities 7M and 7N (policy foundation)
A bounded rolling native sender monitor measures payload bitrate, submitted video FPS, queued bytes/packets, recent late frames and sample age from actual publisher counters. It distinguishes unavailable, warming-up, normal, queue pressure, stalled, stale and ended states; counters resetting begin a new measurement epoch. Analytics exposes read-only status and never presents rehearsal metrics as real media. Payload rate excludes protocol/TLS overhead, and submitted FPS is not receiving-side FPS. Thresholds (4 MiB/96 queued packets, 2 seconds without sent-packet progress) are initial diagnostic defaults, not verified production limits. The separate pure reconnect policy permits only explicitly classified transient transport failures while authorized, with 1/3/9-second delays, at most three attempts within a 30-second recovery window; cancellation, revocation, unknown faults, denied publishing, certificate failures and local media errors terminate recovery. Fresh connection/encoder/IDR/codec configurations are mandatory. Policy is not yet wired to an actual retry loop; automatic reconnection remains disabled. Core coverage remains 8/20. No network or installer action was performed.

## Priority 7N — Native recovery orchestration
The internal, explicitly authorized macOS RTMPS session now drives fresh capture/encoder/publisher epochs through the bounded retry policy. Only typed, recognized transient TCP-connect or post-authorization socket read/write errors qualify; ambiguous TLS/handshake/protocol errors, explicit server stop, EOF, local encoder/source faults and unknown failures remain terminal. A retry discards old queues and opens new native sources, codecs, initial IDR/configuration and a new authorized publisher. Retry waits are cooperatively cancellable; the dashboard reports the retry state and attempt number, with per-epoch counters. At most three retry attempts (1/3/9-second backoffs) can be initiated inside the 30-second recovery window and requested duration plus 30-second outer scheduling budget. Blocking OS DNS, negotiation, source startup, writes and drain can overrun the scheduling budget; this is not a hard wall-clock guarantee. A successful final report describes the last successful epoch, not gapless or aggregated delivery. Recovery is currently internal only, requires the caller's explicit authorization, and cannot be initiated from the production UI. No automatic retry after final drain failure, no Windows live encoder, and no real receiver or hardware validation yet. Regression tests cover classified write faults versus unknown faults, explicit server stop, retry sequencing and cancellation. No actual broadcast, installer or release was initiated. Core coverage remains 8/20 pending complete integration.

## Priority 8A–8B — Local secure destination management
Mac Keychain and Windows Credential Manager use explicit keyring 3.6.3 native backends. Destination label, endpoint and stream key are stored together in the OS vault, with a UUID-only empty-file index in the app data directory. Local list/add/remove operations are serialized per process; list responses omit the stream key and the native-only credential resolver requires explicit authorization. The Multistream workspace supports up to eight saved RTMPS destinations, write-only key entry, removal confirmation and missing-credential reporting. Saving is not authorization to connect; no network, OAuth, actual Go Live, API credential export or remote platform linking. The existing destination URL validator rejects insecure RTMP, embedded user credentials, queries and fragments. Users must enter stream keys only in the key field; labels and server URLs are displayed. Key rotation is add-new then remove-old; no in-place editing. Vault errors do not fall back to plaintext. Native OS prompts, actual vault persistence, multi-process access, index backup/recovery, memory zeroization and deletion/authorization races at future live start require acceptance and further integration. Mock repository and UI tests plus opt-in native credential roundtrip added. Linux, Android and web vaults unsupported. Core coverage remains 8/20 until destination authorization and handoff are integrated and reviewed.

## Priorities 8D–8E — Native multistream fanout and failure isolation
The composed native Program encoder produces one A/V batch and fans it out to independent authorized publishing workers. Up to three simultaneous destinations (eight saved in the vault) are allowed in this initial bounded diagnostic. Each has an independent mailbox, queue, pacing, inbound control and output counters; failure or backpressure in one worker does not terminate healthy workers. All selected saved destinations must have confirmed previews and process-local credential leases. Connections negotiate concurrently before media admission; initial negotiation is all-or-nothing, although a successfully negotiated server may have received its publish command before another rejects. No stream media is admitted until all are authorized. After startup, a partial failure is visible in Analytics and the final result is not reported as full success; remaining destinations drain their admitted packets. Single-destination recovery remains supported; per-destination automatic reconnection while other destinations continue is not implemented because it requires fresh configuration/IDR and timestamp rebasing. Current aggregate stats sum payload bytes and queues, not per-stream bitrates, and do not prove receipt. Tests simulate server-stop isolation, continued sending/drain and duplicate ID rejection. The actual live UI is still gated. OS DNS, capture startup and in-flight socket calls remain cooperatively bounded rather than hard deadlines. This is an internal 2–60 second Mac/Windows diagnostic, not sustained production broadcasting. No real endpoints, installers or releases were invoked. Core workstream count remains 8/20 until integration gates are satisfied.

## Workstreams 9/10/12 — independent destination recovery
For an explicitly authorized two- or three-destination native test, each output now has an independent asynchronous connector and bounded recovery policy. Only classified transient socket errors trigger a retry. A recovered worker waits for the next shared encoder IDR, resends cached AVC/AAC configuration at timestamp zero, rebases subsequent packet timestamps, and discards audio predating that IDR. Surviving outputs retain their original encoder and timeline. Retry delays are 1/3/9 seconds, with at most three attempts in a 30-second window measured from the first failure of that destination for the entire session; subsequent failures outside the window are terminal. Unknown, certificate, server-stop, media and queue faults are not retried. No stale media is replayed. Sender counters accumulate across that destination's epochs, with interruption and retry count exposed in Analytics. Any interruption prevents a clean acceptance result even if recovery and final drain succeed. Cancellation stops scheduling/rejoining, but an already-blocking OS negotiation can outlive the capture or lease; no media is admitted to a late worker. Actual network, device and receiver soak remain unverified. Unit tests exercise IDR rejoin and synthetic isolated transport failure. This increment does not enable default production Go Live or change formal core coverage.
