# Native rolling replay buffer — priority 10A (first increment)

The native Mac/Windows Program pipeline can encode AVC/AAC into a rolling in-memory replay ring and export a keyframe-aligned FLV clip on successful capture completion. The ring retains codec configurations, complete GOPs and validated media packets. The nominal window is 2–30 seconds, the full capture is 2–60 seconds, and media payload storage is bounded by 32 MiB and 4096 packets (plus bounded config, temporary packet and export allocations). Old GOPs are evicted based on the latest video timestamp or capacity; a single oversize GOP fails closed. The exported window may be shorter under memory pressure or slightly longer due to keyframe alignment. Codec configurations and first IDR start at zero, delayed audio before the start or beyond the last video timestamp is dropped, and remaining media is sorted by timestamp with video first at equal timestamps. AAC priming/tail and actual independent playback are not verified.

In Studio choose an output profile and a capture duration, open Capture diagnostics, select Replay window, then **Capture and save rolling replay**. No always-on capture, hotkey, instant snapshot during a running stream, background service or real network connection. The result includes retained video frame count, nominal output duration and total captured video frame count. Other acquisition/audio counters describe the whole capture, not the exported window. The private file is synced and published without replacing an existing clip, using the existing FLV inventory path. Failed export removes the partial file. No installer or release action.

Regression tests cover GOP eviction, timestamp rebasing, AAC ordering, malformed media, oversized GOPs and simulated browser routing. Physical-device test, independent decoder verification, rolling live-session export and global save hotkey remain outstanding. Workstream 15 is partial; the formal core coverage count remains 8/20.
