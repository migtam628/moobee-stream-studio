# RTMP publish protocol foundation (offline)

`stream_mux::rtmp` adds simple RTMP v3 handshake messages, AMF0 connect/createStream/publish payloads, and bounded fmt-0/3 chunk serialization with extended timestamps. Existing AVC/AAC media packets can be routed to distinct chunk streams once a message stream ID is assigned. The current module never opens a socket, stores secrets, contacts streaming services or changes Go Live. All fixture keys are synthetic. The eventual network layer must enforce TLS certificate validation and timeouts, use CSPRNG handshake randomness, parse bounded incoming chunks and AMF command responses, negotiate window acknowledgement and chunk size, respond to ping/control messages, wait for NetStream.Publish.Start, handle authentication/reconnect/backpressure and feed live encoder packets rather than a completed MP4. Simple handshake only; complex/signed handshakes and platform compatibility remain untested. No actual RTMP or RTMPS stream has been published. No installer requested.

Tests cover wire headers, endianness, extended timestamps, continuation chunks, handshake echo validation, AMF0 commands and existing AVC/AAC packet routing. The Mac CI filter `stream_mux::tests` includes `stream_mux::tests_rtmp`.

## Priority 7B — inbound protocol and publish authorization
The bounded decoder supports interleaved fmt 0–3 chunks, compressed headers, extended timestamps, chunk-size changes and abort. It limits messages to 1 MiB, pending message storage to 4 MiB and chunk streams to 32. AMF0 parsing bounds string sizes, recursion and value counts. Negotiation requires matching connect and createStream transaction results, a positive assigned stream ID and an explicit NetStream.Publish.Start on that ID; rejects server errors without exposing response text. It produces acknowledgement and ping-response actions. A real transport, timeouts, peer bandwidth handling, server interoperability and live packet producers remain separate work. No network access or installer requested.

## Priority 7C — transport and publishing session
The generic Read/Write publisher joins handshake, connect/createStream/publish, server authorization, acknowledgement and ping handling, and media writes. In-memory server transcripts exercise success, rejection and stop. A native macOS/Windows RTMPS adapter uses the OS TLS trust store with hostname/certificate validation and TLS 1.2 minimum, OS randomness, bounded TCP connection and negotiation/I/O deadlines. Plain RTMP, URL credentials, query and fragment, and IP-literal endpoints are rejected; pass the stream key separately, with no error echo. OS DNS resolution is blocking and must run away from the UI. The session is not yet invoked by UI or capture; continuous inbound servicing and live encoded packet scheduling, bandwidth controls, platform compatibility, reconnect and key storage are still outstanding. No external service was contacted, no real certificate handshake tested, no installers requested.

## Priority 7D — bounded media delivery queue
A per-session queue accepts up to 512 encoded packets, 8 MiB payload total and 2 MiB per packet. It requires AVC configuration, an initial IDR, AAC configuration before raw audio, valid NAL lengths and monotonic per-track timestamps. Overflow or invalid packets fail closed and require a new session/epoch rather than silently dropping compressed dependencies. The publisher can drain one queued packet at a time after publish authorization; the synthetic transcript now exercises queued AVC/AAC configuration and IDR delivery. Actual native packet producers, a concurrent inbound/outbound scheduler, reconnect and multi-destination ownership are not implemented. No production connection or installer requested.

## Priority 7E — native macOS AVC packet extraction
Adds a direct VideoToolbox H.264 encoder for the existing 360p10, 720p15 and 1080p30 profiles and 1.5/3/6 Mbps presets. It accepts composed RGBA, disables frame reordering, requests initial/forced IDR frames, extracts bounded four-byte-length AVCC access units and SPS/PPS, and emits FLV AVC sequence/media packets for the existing bounded queue. Codec configuration changes fail closed. No MP4 file, external encoder, network or UI action is used. This is a synchronous diagnostic bridge; flushing each frame and driver stalls may limit throughput. Actual encoder execution is an explicitly ignored synthetic test requiring functioning macOS VideoToolbox; ordinary CI type-checks/links the bridge and tests AVCC parsing. Native AAC packet extraction, Windows packet producer, continuous scheduler, real capture integration, rate control acceptance and hardware tests are pending. No installers requested.

## Priority 7F — clocked packet pump
A deterministic tick function paces queued packets against a supplied monotonic elapsed clock, sends at most eight due packets per invocation, returns the next due timestamp and counts successfully sent packets and payload bytes. It fails closed after more than two seconds of media lateness, on backward clock movement or send error; stop clears the queue. This is the scheduler core, not a running background thread. The eventual session owner must manage writable/readable transport, bounded deadlines, concurrent inbound controls, native video and audio producers, and reconnect epochs. Tests use synthetic packets and no network. No installer requested.

## Priority 7G — native macOS AAC packet extraction
The AVAudioConverter bridge accepts 48 kHz stereo float PCM, uses AAC-LC at a 128 kbps target with 1024-frame packets and no priming request, and returns bounded length-prefixed raw access units. Rust collects partial PCM blocks, validates packet sizes and timelines, emits the existing AAC configuration and sample-clocked RTMP packets, and rejects excessive encoder delay. Native execution, independent decoding and exact encoder priming/A-V alignment remain unverified; final partial blocks are discarded at stop. No MP4 or network connection. Ordinary native CI compiles the bridge and tests parsing; the synthetic tone encoder test is opt-in. No installer requested.
