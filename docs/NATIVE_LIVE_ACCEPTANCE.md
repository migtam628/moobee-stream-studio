# Developer-only real stream acceptance — priority 8G

The default desktop build continues to disable real Go Live. An explicitly enabled Cargo feature, `native-live-acceptance`, compiles a local Mac/Windows acceptance interface for a 2–60 second real RTMPS test against one to three saved destinations. CI only compile-checks this feature; it does not launch the app or send a stream. Release CI must not enable it until production acceptance is complete.

When enabled by a developer, Studio displays a separate real stream test panel. Select saved private test destinations, review the frozen Program capture source/audio/profile/duration and destination names/URLs, and type START REAL TEST STREAM. Only that explicit action calls native start. The backend verifies the feature, phrase, session ID, limits and confirmed destination previews, then uses the existing OS-vault credential handoff. The webview receives no stream key. The session status shows sent-packet/frame counts, not receiver verification. Stop is session-scoped and cooperative; OS DNS and in-flight I/O are still not instantly interruptible. Leaving Studio requests stop. The command stays pending until the worker returns, preventing local preview handoff during the test. A stop before native dispatch cancels the pending start. Cancellation/failure during startup may appear as failed rather than stopped.

This is an opt-in test build, not a security boundary against a compromised local webview. The ordinary build must remain disabled, no automatic start, no remote HTTP start, no installer execution or actual stream is part of this change. Real receiving-side quality, hardware, long-running output, independent destination recovery and security review remain required. Tests simulate the UI and validate native intent checks without connecting to any endpoint.
