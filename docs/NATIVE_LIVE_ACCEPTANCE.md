# Developer-only real stream acceptance — priority 8G

The default desktop build continues to disable real Go Live. An explicitly enabled Cargo feature, `native-live-acceptance`, compiles a local Mac/Windows acceptance interface for a 2–1800 second real RTMPS test against one to three saved destinations. CI only compile-checks this feature; it does not launch the app or send a stream. Release CI must not enable it until production acceptance is complete.

When enabled by a developer, Studio displays a separate real stream test panel. Select saved private test destinations, review the frozen Program capture source/audio/profile/duration and destination names/URLs, and type START REAL TEST STREAM. Only that explicit action calls native start. The backend verifies the feature, phrase, session ID, limits and confirmed destination previews, then uses the existing OS-vault credential handoff. The webview receives no stream key. The session status shows sent-packet/frame counts, not receiver verification. Stop is session-scoped and cooperative; OS DNS and in-flight I/O are still not instantly interruptible. Leaving Studio requests stop. The command stays pending until the worker returns, preventing local preview handoff during the test. A stop before native dispatch cancels the pending start. Cancellation/failure during startup may appear as failed rather than stopped.

This is an opt-in test build, not a security boundary against a compromised local webview. The ordinary build must remain disabled, no automatic start, no remote HTTP start, no installer execution or actual stream is part of this change. Real receiving-side quality, hardware, long-running output, independent destination recovery and security review remain required. Tests simulate the UI and validate native intent checks without connecting to any endpoint.

## Sustained acceptance and orderly stop
The developer-only real test panel now has an independent duration selector (4, 15, 30, 60, 300, 900 or 1800 seconds). The backend caps the entire requested media epoch at 30 minutes, below the existing one-hour encoder limit. It still fails closed if timing or source freshness budgets are exceeded. A successful worker drain sends RTMP deleteStream for the assigned message stream before dropping the connection. It does not wait for receiver acknowledgement, and transport write failure is not a successful stop. Emergency cancellation/fault paths may close the transport directly. The recovery scheduler is cooperative and can exceed its nominal outer time budget during blocking OS calls; a retry's last epoch is not proof of uninterrupted delivery.

Workstream 9 acceptance: first validate a private receiver with a 4-second test, then a 1-minute test, then 5/15/30-minute tests with independent receiver-side A/V inspection, stream termination and sender-versus-receiver counts. Record platform/OS, profile, duration, source/audio selection, receiver decode result, interruptions, and stop behavior; never store stream keys in logs. No real acceptance test has been executed. The two-hour production gate requires further encoder epoch handling, soak testing and review; no production build flag or release gate is changed.
