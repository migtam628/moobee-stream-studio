Scope: source review of the native RTMPS connector, publisher, destination vault, recovery fanout, acceptance IPC and desktop configuration. Not an independent penetration test or full dependency audit.

The negotiation permit is deliberately removed after successful authorization so an explicit stop can drain admitted media and send deleteStream. The transport keeps the credential lease until it is destroyed. No cancellation policy can unsend bytes already transmitted. Tests cover a pre-cancelled connection, revoked socket permit (local loopback only), and shared lease lifetime. Existing worker, fanout, receiver and credential tests remain in place. No actual public stream, installer execution or release. Production Go Live stays gated pending native runtime/physical receiver acceptance, two-hour soak, and further security validation.

## Bounded DNS cancellation
The connection caller waits at most five seconds for DNS and checks its revocable permit approximately every 25 ms. The OS resolver runs in a detached, process-wide capped worker pool (at most four concurrent outstanding resolver threads, including abandoned ones). A timed-out worker holds its slot until the underlying OS call returns; new requests fail closed when slots are exhausted. Resolver workers receive only the hostname and port, not credentials, leases, sockets, or publishing state. No connection is opened by a resolver thread, and a late result is discarded after timeout or cancellation. DNS errors, saturation and timeout remain conservatively non-retryable under the existing recovery classification. DNS resolution itself and in-flight TCP/TLS operations are not instantly interruptible. Unit tests exercise the result-channel deadline and revoked permit without external DNS. Actual OS-resolver delay and network cancellation require hardware/network acceptance.

## Authorized receiver disconnect recovery
After RTMP publish authorization, an EOF from the TLS transport without a parsed terminal protocol command is treated as a transport interruption eligible for the existing bounded recovery policy. An incomplete buffered inbound chunk or unfinished multi-chunk message reassembly remains ambiguous and is not classified as a retryable transport read failure. Explicit RTMP publish stop/denial, malformed control messages and certificate errors remain terminal. The application never automatically creates a new user authorization; a retry is limited to the existing authorized session and destination. A test-only local TLS receiver exercises both EOF and explicit RTMP Publish.Stop; this is not proof of live network or external provider interoperability. A server may close a connection without declaring its reason, so retry remains bounded and any interruption disqualifies uninterrupted soak acceptance.

A second encrypted loopback integration regression supplies structurally valid synthetic video packets to two independent publishing workers, disconnects one receiver after initial media, and verifies a fresh local receiver starts at a new IDR with zero-based timestamps while the healthy receiver receives every submitted frame. Both receiver reports must confirm orderly closure, and the overall interrupted run must not report clean soak completion. This uses protocol-valid fixture payloads, not independently decoded video from physical capture; native codec decode remains separately covered by CI.
